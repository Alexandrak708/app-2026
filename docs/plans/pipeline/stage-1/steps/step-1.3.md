# Step 1.3 — Define the `University` TypeScript Type

## What this step does

Creates a single TypeScript type that mirrors your `universities` Supabase table. Every part of the app that touches university data imports from this one file. When you add a column to the table later, you update the type here and TypeScript surfaces everywhere that needs updating.

---

## 1. Create the types folder

If `lib/types/` does not already exist in your project, create it:

```
your-project/
└── lib/
    └── types/
        └── university.ts   ← create this
```

You can create the folder by simply creating the file — your editor and TypeScript will handle the rest.

---

## 2. Create `lib/types/university.ts`

```ts
export type University = {
  id: string;
  name: string;
  country: string | null;
  city: string | null;
  website: string | null;
  admissions_email: string | null;
  description: string | null;
  created_at: string;
  updated_at: string;
};

export type ApplicationRequirement = {
  id: string;
  university_id: string;
  label: string;
  required: boolean;
  format: string | null;
  notes: string | null;
  created_at: string;
};

export type ApplicationHistory = {
  id: string;
  university_id: string;
  university_name: string;
  program: string;
  student_name: string;
  file_names: string[];
  email_subject: string | null;
  user_id: string | null;
  sent_at: string;
};
```

All three table types are defined here. You only use `University` in Stage 1, but defining the others now means every future stage already has its type ready.

---

## 3. Why `string | null` and not just `string`

Every nullable column in Supabase returns either a string value or `null` when the field is empty. If you type a nullable column as just `string`, TypeScript will not warn you when you try to use it without a null check — which means bugs like rendering `undefined` on screen or passing `null` into a function that expects a string.

Typing nullable columns as `string | null` forces you to handle the null case explicitly. For `admissions_email` specifically, this is the mechanism that makes the conditional Apply button work — TypeScript enforces that you check `admissionsEmail !== null` before treating it as a valid string.

---

## 4. Optional — generate types automatically from Supabase

If you have the Supabase CLI installed and linked to your project, you can generate types directly from your live database schema instead of writing them by hand:

```bash
npx supabase gen types typescript --project-id your-project-ref > lib/types/database.types.ts
```

Replace `your-project-ref` with the ID from your Supabase dashboard URL.

This generates a full typed schema including all tables, views, functions, and enums. If you go this route, import the generated types into `lib/types/university.ts` and re-export them under the simpler names used throughout the app:

```ts
import type { Database } from './database.types';

export type University = Database['public']['Tables']['universities']['Row'];
export type ApplicationRequirement = Database['public']['Tables']['application_requirements']['Row'];
export type ApplicationHistory = Database['public']['Tables']['application_history']['Row'];
```

Either approach works. Hand-written types are simpler to start with. Auto-generated types are better long-term as your schema grows.

---

## 5. Add a utility type for inserts

You'll need this in Stage 5 when writing application history records. Add it to the same file now so you don't have to come back:

```ts
export type NewApplicationHistory = Omit<ApplicationHistory, 'id' | 'sent_at'> & {
  sent_at?: string;
};
```

`Omit` removes `id` and `sent_at` (both are auto-generated by Supabase). The `& { sent_at?: string }` makes `sent_at` optional for cases where you want to override it explicitly.

---

## 6. Verify TypeScript resolves the import

In any existing component that uses university data, try replacing any inline type or `any` with the new import:

```ts
import type { University } from '@/lib/types/university';
```

If your `tsconfig.json` has `"paths": { "@/*": ["./src/*"] }` or similar path alias configured, the `@/` prefix resolves to your project root. If you don't use path aliases, use a relative import:

```ts
import type { University } from '../../lib/types/university';
```

Run `npx tsc --noEmit` to confirm there are no TypeScript errors before moving on.
